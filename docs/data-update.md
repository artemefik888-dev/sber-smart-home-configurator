# Обновление данных

## Через интерфейс

Откройте этап «07 Обновление данных» и загрузите два файла:

1. файл типовых расчётов с четырьмя листами квартир и листом `Сценарии`;
2. актуальный каталог с листом `Sber` либо первым листом с той же табличной структурой.

До кнопки «Применить» проверяются:

- наличие пяти обязательных листов;
- наличие четырёх типов квартир;
- количество товаров и используемых SKU;
- отсутствующие и дублирующиеся SKU;
- числовые неотрицательные цены;
- внешние формулы цены без сохранённого значения;
- известная ошибка заголовка 3К;
- известный пропуск ванной в формуле белого итога 2К.

Критические ошибки блокируют применение. Ошибки заголовков и итоговых формул показываются как предупреждения, потому что приложение использует имя листа и собственный построчный пересчёт. Применённая через браузер версия хранится только локально на текущем устройстве.

## Обновление встроенной опубликованной версии

1. Замените `source-data/typical-apartments.xlsx` и `source-data/catalog-2Q-2026.xlsx`.
2. Запустите нормализацию:

```bash
python3 scripts/build_default_data.py
```

3. Проверьте контрольные условия:

```bash
pnpm test
pnpm lint
pnpm build
```

4. Просмотрите отчёт скрипта: `missingSku`, `duplicateSku`, `invalidPriceSku` и `externalPriceFormulasWithoutValue` должны быть пустыми или равны нулю.
5. Выполните новое сохранение версии и развёртывание Sites.

Скрипт также извлекает изображения из каталога в `public/products/`, когда строка изображения однозначно связана со SKU.
