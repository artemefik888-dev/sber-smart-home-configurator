# Структура данных

Основной контракт описан в `app/data/types.ts`, встроенный набор — в `app/data/default-data.json`.

## SourceData

- `meta` — версия, дата прайса, валюта, минимальная сумма заказа и источник;
- `apartments` — четыре типа квартир и ключи условных планировок;
- `catalog` — товары: `sku`, официальное название, описание, цена, изображение, отметка и строка источника;
- `readyRows` — строки типовых наборов: квартира, цвет, SKU, количество, помещение, категория, подарок, рекомендуемый модуль и исходная строка;
- `scenarios` — группы «Свет», «Климат», «Безопасность» с вводным текстом и списком сценариев;
- `diagnostics` — результат аудита источников.

## Проект пользователя

`ConfiguratorProject` содержит название, номер, квартиру, цвет, режим, независимые наборы выбранных помещений, выбранные категории, переключатели подарка и протечек, ручную корзину и четыре поля самопроверки. Проект сохраняется в `localStorage`.

## Расчёт

1. Для готового режима выбираются строки по квартире и цвету.
2. Применяется фильтр помещений или категорий.
3. Подарок исключается только при выключенном переключателе.
4. Рекомендуемые строки протечек включаются через категорию «Безопасность» или отдельный переключатель, но остаются уникальными по исходной строке.
5. Каждая строка соединяется с каталогом по SKU.
6. Цена берётся только из каталога, сумма строки равна `количество × цена`.
7. Общий итог, количество устройств и число уникальных SKU собираются из подробных строк.

Если SKU отсутствует или его цена некорректна, строка не маскируется: экспорт блокируется, а интерфейс показывает перечень проблемных SKU.

В ручном режиме спецификация строится из `manualCart`. Хаб автоматически не добавляется: интерфейс лишь предупреждает о его отсутствии.
